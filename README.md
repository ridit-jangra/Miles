# Miles

A voice harness that runs on your machine with multiple `tts`, `stt` & `llm` providers to choose from. You talk to it and it talks back. it can handle subagents, multiple tool calling, calling subagents in parallel while you keep chatting with it.

Built on [Pipecat](https://github.com/pipecat-ai/pipecat). `TTS (Text to Speech)`, `LLM (Large Language Model)` & `STT (Speech to Text)` are all swappable through `config.toml`.
Miles can get more tools, mcps & subagents through plugins. Miles is shipped with no plugins so its zero bloat.

## Features

- **Customiziblity:** choose any provider you like, change it in `config.toml` and miles adapts to it. Miles auto-installs it and auto download its models.
- **Background agents:** Miles can spawn background agents to do longer tasks or do things it can't do itself, so you can keep chatting with it while it does the work in background.
- **Memory:** Miles can remember the facts you tell him to remember and it can remember facts from your conversations (you can turn off auto remember from `config.toml`).
- **Alerts:** A full inbox system from where Miles can read alerts that plugins sent.
- **Confirmations:** Miles ask for your permission before doing risky actions.
- **Desktop app:** an Electron window that tells you everything that is going on.

## Installation

### Installing locally

You need:

- [git](https://git-scm.com), [uv](https://docs.astral.sh/uv/) (it fetches Python 3.12 for you) and [bun](https://bun.sh)
- [Node](https://nodejs.org) 18 or newer, only if you use the `browser` plugin (its Playwright server runs on Node)
- Google Chrome, only for the `browser` plugin
- An API key for an online language model, and the speech models run locally.

Clone the repository
```bash
git clone https://github.com/ridit-jangra/miles
```

Make a .env file
```bash
cp .env.example .env # then put llm/stt/tts api keys according to our provider
```

Install dependencies
```bash
uv sync
cd ui && bun install && ./node_modules/.bin/install-electron && cd..
```

Run it
```bash
bun run dev
```

> If you only wanna run the server with no electron client, run `uv run src/miles/main.py`

Things to know that happens on the first start:
- THe local speech models are downloaded, a few hundered MBs. The loading screen also shows the progress.
- If you copied the plugins, the loading screen will ask what plugins you wanna install, you can install all of them or just install a few.
- Bun skips Electron's install script, which is why step 5 fetches the binary by hand.
- Closing the app also stops the server

To remove data that Miles stores outside the repo, delete `~/.miles` (plugins, trust list) and the model caches at `~/.cache/piepcat` and `~/.cache/huggingface`

## Configuration

All the configuration lives in `config.toml` at the repo root. Secrets go in `.env` never in the config or a plugin.

`.env`
```bash
LLM_API_KEY=... 
STT_API_KEY=...   # only set if you're using an online service, skip if it runs locally
TTS_API_KEY=...   # only set if you're using an online service, skip if it runs locally
```

```toml
[llm]            # the voice model
provider = "openrouter"
model = "anthropic/claude-haiku-5.5"

[agents]         # the model background agents use
provider = "openrouter"
model = "anthropic/claude-sonnet-5-5"

[stt]            # speech to text
provider = "whisper"
model = "small"

[tts]            # text to speech
provider = "piper"
voice = "en_US-danny-low"

[plugins]
enabled = true   # false turns off every plugin and every agent
disabled = []    # plugin names to skip

[memory]
history_days = "never"   # a number of days, or "never"

# Use these only if you install the plugins

[plugin_settings.weather]
city = "Delhi"
units = "metric"         # or "imperial"

[plugin_settings.calendar]
country = "IN"           # two letter code, for holidays
```

## Making a custom plugin

Making a plugin is easy and it can be build using python

Basic structure of a plugin
```text
your-plugin-dir/
  plugin.toml       all the configuration for your plugin
  plugin.py         the logic of your plugin
  agents/           all the agents live here
    agent.md        the agent file
```

> The code is generated by claude

`plugin.toml`
```toml
name = "example"                          # shown in the UI; keep it the same as the folder name
description = "One line shown on the approval screen and the Plugins page"

[permissions]                             # shown to you when approving; free-form, they list what it touches
network = true
shell = true

[dependencies]
python = ["feedparser>=6", "psutil>=5.9"] # installed with uv after you approve, into ~/.miles/deps/example

[miles]
tools = ["quick_tool"]                    # only these tools go to Miles; agents still get all of them
# tools = false                           # none go to Miles, agents only
# leave the section out and every tool goes to Miles

[mcp.playwright]                          # a local server, started with a command
command = "bunx"
args = ["@playwright/mcp@0.0.83", "--output-dir", "~/.miles/data/browser"]   # ~ and $VARS are expanded
miles = false                             # true gives this server's tools to Miles himself
tools = ["browser_navigate", "browser_snapshot", "browser_click"]            # allowlist; leave out for all

[mcp.remote]                              # a remote server, started with a url
url = "https://example.com/mcp"           # set command OR url, never both
```

`plugin.py`

> `register(api)` gets a `PluginContext`:

```python
def register(api):
    @api.tool
    async def my_tool(arg: str) -> dict:
        """The docstring is what the model reads, so write it for the model."""
        return {"ok": True}

    @api.watch(every="5m")       # 30s, 5m, 1h
    def check_something():
        ...                      # return Alerts for the inbox

    # api.confirm(question, action) asks the user before a risky action
    # api.quiet(seconds) and api.quiet_off() hold back non-urgent alerts
    # api.config is the plugin's [plugin_settings.<name>] table
```

An agent file:

```markdown
---
name: lookup
description: One sentence the voice model reads to decide when to delegate.
tools: [wikipedia, define]
mcp: [some-server]        # optional
model: anthropic/claude-haiku-5.5   # optional, defaults to [agents] in config.toml
max_steps: 4
---
The agent's instructions. Keep answers to a few spoken sentences, no markdown.
```

Tings to know:

- **Plain functions run on the event loop.** A slow sync tool freezes the voice audio. Make slow tools `async` and use `asyncio.to_thread` for blocking work.
- **Tools return plain dicts**, never dataclasses. Return `{"error": "..."}` for failures the model can say out loud.
- **Packages:** list them under `[dependencies] python = ["feedparser>=6"]`. They are installed with `uv` into `~/.miles/deps/<plugin>` at startup, after you approve the plugin. Plugins share one Python process, so two plugins that need different versions of one package can clash. An MCP server run through `uvx` or `bunx` is isolated and avoids that.
- **MCP servers:** declare them under `[mcp.<name>]` with `command` and `args` (`~` and `$VARS` are expanded). Add `miles = true` to give the server to Miles himself, and `tools = [...]` to allow only some of its tools. Without `miles = true`, only agents that list it under `mcp: [name]` can use it.
- **Agents versus Miles:** `[miles] tools = false` (or a list of names) keeps a plugin's tools away from Miles so he delegates to the plugin's agent instead. Agents name the tools they use in their frontmatter and can use all of the plugin's tools. Keep any tool that calls `api.confirm` on Miles, because an agent can't ask you yes or no.
- **Scoping:** an agent only sees its own plugin's tools and MCP servers.

## Trust for plugins

Plugins run Python code inside the server, and their manifests install packages and launch programs. Plugins in `~/.miles/plugins` must be approved by you first. The approvel is stored in `~/.miles/trust.json`.

> NEVER INSTALL A PLUGIN U DON'T TRUST OR U HAVEN'T CHECKED THE CODE OF, IT CAN RUN SUS THINGS ON YOUR COMPUTER OR LAPTOP
